# Проверка первого среза Core

## Изолированные тесты

Из корня проекта запустите `luajit tests/unit/profile.lua` с LuaJIT,
совместимым с Lua 5.1. Тест загружает точку входа Core с подставными событиями
MWSE и проверяет создание профиля, переключение между слотами, миграцию
0 → 1 → 2 → 3 → 4 → 5, однократное начисление за каждый подтверждённый источник
при изменении журнала и загрузке старого сохранения, а также защиту
будущих версий.
Тест подтверждает сохранение данных регионального пилота и отсутствие
новых начислений за возврат кольца Фарготу.

Запустите `luajit tests/unit/goldDialogue.lua` для проверки адаптера золота
и двух веток диалога. Тест проверяет ноль, границу 99/100, изменение суммы
между вызовами, отсутствие игрока и открытие темы при загрузке сохранения
с активным ESP. Для репутации тест проверяет ноль, повторное чтение
после изменения и ответ при недоступном объекте игрока.
Для Телванни проверяются действующее членство, начальный ранг с индексом
0, изменение ранга и репутации, отсутствие членства, исключение и
недоступная фракция.
В том же вызове тест проверяет вывод расы, региона, отношения собеседника
и ответ при отсутствии этих данных.
Тест запускает Core с диагностическим ESP и без него. В обоих случаях
изменение отношения остаётся за движком.
Запустите `luajit tests/unit/telvanniSupplies.lua` для проверки права
на припасы, границы 168 часов, общей выдачи, сбоя одной позиции и
независимости отметок в разных сохранениях и у разных видов припасов.
Проверка разных поставщиков подтверждает общие сроки выдачи Телванни.
Вызов обработчика от имени Аррилла игнорируется даже на профиле с
региональными данными.
Запустите `luajit tests/unit/socialStatus.lua` для проверки MCM перед
загрузкой, с отключённым ESP, во время ожидания и при доступных припасах.
Каждое открытие читает актуальные значения и сохраняет отметку выдачи.

## Проверка в Morrowind

1. Установите Core по [README](../README.md) в отдельный тестовый профиль.
   Запустите игру без ESP GHSO. В `MWSE.log` должно появиться сообщение
   `Core initialized`. При загрузке сохранения без профиля или в новой игре
   ожидается `Created profile with schema 5` без Lua-ошибок.
2. Для проверки значений используйте тестовые сохранения и режим Lua
   [в консоли UI Expansion](https://github.com/NullCascade/morrowind-mods/blob/master/User%20Interface%20Expansion/MWSE/mods/UI%20Expansion/MenuConsole.lua).
   Введите `tes3.player.data.GHSO.player.testMarker = "A"`, затем
   `tes3.player.modified = true` и сохранитесь в слот A. Повторите с
   `"B"` для слота B. Перезапустите игру. Загрузите A, затем B и проверьте
   `print(tes3.player.data.GHSO.player.testMarker)` в каждом. После начала
   новой игры ожидается `nil`.
3. Загрузите копию старого сохранения с версией 4. Ожидается миграция
   4 → 5 с сохранением `testMarker`, влияния и срока выдачи припасов.
   Таблица региональных начислений создаётся пустой.
4. На отдельной копии сохранения со строкой `testMarker` задайте
   `tes3.player.data.GHSO.schemaVersion = 6` и `tes3.player.modified = true`.
   Сохранитесь, загрузите слот и проверьте журнал. Core должен сообщить,
   что пропустил более новую схему. После повторного сохранения и загрузки
   версия 6 и значение `testMarker` должны сохраниться.

## Результат игрового прогона

Владелец проекта подтвердил по `MWSE.log`, что при первом запуске Core
создал профиль, а при повторной загрузке прочитал существующий профиль.
Владелец проекта подтвердил общий прогон у Фаргота в рабочем профиле.
Тема открывается и за один выбор корректно показывает золото, общую
репутацию, членство, ранг и репутацию в Доме Телванни, расу, регион и
эффективное отношение собеседника.
На сохранении с уже сданным заданием Рейвен Омэйн подтверждено влияние 1.
После перезапуска значение осталось равным 1.
Объединённое начисление за поддерживаемые задания также проверено владельцем
проекта в игре.
Отдельного игрового подтверждения для двух слотов, миграции и сохранения
данных будущей версии пока нет.

При проверке тестового диалога изолированная копия Morrowind завершалась
с ошибкой `0xC0000005` до главного меню. Ошибка повторилась в контрольном
запуске без Lua-мода GHSO и без тестового ESP. Поэтому сценарии двух слотов
и диалога на этой копии остались непроверенными в игре.

## Диалог Фаргота

Включите `GHSO Gold Check.esp` из свежего архива после `Morrowind.esm`,
перезапустите игру и загрузите тестовое сохранение. У Фаргота в Сейда Нин
выберите `GHSO Gold Check` один раз. Сверьте весь ответ за этот разговор:

| Поле | С чем сверить |
| --- | --- |
| `Current gold` | Сумма золота в инвентаре. |
| `General reputation` | Общая репутация в характеристиках. |
| `House Telvanni`, `Rank`, `Faction reputation` | Членство и название ранга в списке фракций. Число репутации можно уточнить через `print(tes3.getFaction("Telvanni").playerReputation)`. |
| `Race`, `Region` | Раса персонажа и регион текущей внешней ячейки. |
| `Disposition` | Эффективное отношение Фаргота в окне разговора. |

Запись `Gold check selected` в `MWSE.log` содержит те же прочитанные
значения. Границы, отсутствие данных и разные статусы Телванни покрыты
изолированными тестами.

### Проверка тестового ESP

В Construction Set проверьте, что у темы одна INFO, фильтр Actor
указывает на `fargoth`, а Results передаёт `reference` в
`GHSO.integrations.goldCheckDialogue`. У общей темы `GHSO Claim Supplies`
должны быть три связанные INFO. Это `8495739601182604271` для
`dalyne arvel`, `7628401109135238643` для `tinaso alan` и
`7029865183740941661` для `garas seloth`. Results у каждой вызывает
`GHSO.integrations.supplyClaims`.

ESP содержит новую тему `GHSO Gold Check` и INFO `8237135861476920419`.
ID проверены на отсутствие совпадений в локальном `Morrowind.esm`.
Ванильная запись Фаргота используется как фильтр. Порог 100 и английские
диагностические реплики относятся к тесту. Заголовок ESP содержит размер
мастера из проверенной локальной установки.

Пересборка исходника из каталога проекта с tes3conv v0.4.1:

```powershell
tes3conv "tests/fixtures/GHSO Gold Check.json" "GHSO Gold Check.esp"
tes3conv "GHSO Gold Check.esp" "GHSO Gold Check.roundtrip.json"
```

Сравните JSON после повторного экспорта с исходником. Совпадение JSON
проверяет записи и Results. Совместимость и отображение темы проверяются
в игре с выбранным порядком загрузки.

Для приложенного ESP обратный экспорт через tes3conv v0.4.1 совпал с
исходным JSON. В бинарном ESP проверены заголовок TES3, последовательность
DIAL/INFO и поле Results.

## Результат пилота отношения Телванни

Владелец проекта подтвердил, что игровой пилот на Далайн Арвел работает.
Дополнительный бонус за ранг удалён из тестовой сборки после прогона.
Ваниль уже учитывает фракционные отношения и ранг, поэтому проверка
подтверждает пригодность события MWSE для отдельной механики GHSO.

## Влияние в Доме Телванни

1. Установите свежий ZIP и загрузите копию сохранения. Для проверки
   отображения включите диагностический ESP и выберите у Фаргота
   `GHSO Gold Check`. Уже выданные очки сохраняются. При первой загрузке
   добавляется по одному очку за каждый поддерживаемый журнал с индексом
   100, если его источник ещё не записан в профиль. Список заданий есть в
   [заметках об API](API_NOTES.md#начисление-влияния).
2. После появления строк `Recorded Telvanni influence +1` сохранитесь
   и загрузите этот слот снова. Общая сумма должна остаться прежней,
   повторных записей начисления в `MWSE.log` быть не должно.
3. Для проверки начисления на событии сдайте любое из поддерживаемых
   заданий на отдельном слоте. Влияние должно увеличиться на 1 сразу,
   до перезагрузки. Начисление работает и при выключенном диагностическом ESP.

## Припасы Телванни

Владелец проекта подтвердил в игре одноразовую выдачу и последующее
возобновление припасов через семь игровых дней.

1. Загрузите копию сохранения версии 3, на котором припасы уже получены.
   У Далайн Арвел, у входа в зал Совета Телванни в Садрит Море, выберите
   `GHSO Claim Supplies`. Ожидается сообщение об оставшихся игровых часах.
   Сохранитесь и перезапустите игру. Отсчёт должен продолжиться с той же отметки.
2. Пропустите шесть игровых дней. На тестовом слоте можно закрыть диалог
   и выполнить в консоли Lua `tes3.advanceTime({ hours = 144 })`.
   Припасы должны оставаться недоступны. Пропустите ещё сутки.
3. Выберите тему. Действующий член Дома с влиянием от 1 получит одно
   стандартное зелье восстановления магии. В журнале появится
   `Claimed privilege: telvanni_supplies` с игровым часом. Повторный
   выбор темы должен показать начало нового семидневного интервала.

[Команда перемотки игрового времени](https://mwse.github.io/MWSE/apis/tes3/#tes3advancetime)

## Страница состояния GHSO

Владелец проекта подтвердил отображение влияния и срока выдачи в игре.

Загрузите тестовое сохранение и откройте `Mod Config → GHSO`. Сверьте
`House Telvanni influence` с ранее подтверждённым значением, а часы
ожидания припасов — с ответом Далайн Арвел. Пропустите игровое время и
откройте страницу снова. Отсчёт должен обновиться, а при доступной выдаче
должно появиться `Available now`.

## Общая выдача припасов

Владелец проекта подтвердил в игре независимые сроки и выдачу доступных
позиций через одну тему.

Обновите Lua и ESP из свежего ZIP. На тестовом слоте с влиянием от 3
откройте `Mod Config → GHSO`, чтобы увидеть оба срока. Если обе позиции
доступны, один выбор `GHSO Claim Supplies` у Далайн Арвел должен выдать
оба зелья и показать один ответ. Если доступна одна позиция, ожидается
только её выдача и отчёт о второй. Повторный выбор показывает оба отсчёта.

## Поставщики Телванни

Владелец проекта подтвердил в игре выдачу у поставщиков и общий отсчёт.

В свежей сборке тема `GHSO Claim Supplies` доступна у трёх поставщиков Телванни.

| Поставщик | Место |
| --- | --- |
| Далайн Арвел | Садрит Мора, вход в зал Совета Телванни. |
| Тиназо Алан | Тель Мора, Tower Services. |
| Гарас Селот | Вивек, алхимик Телванни. |

На тестовом слоте проверьте, что `Mod Config → GHSO` показывает все три
адреса. Получите доступные припасы у нового поставщика, затем выберите ту
же тему у другого до истечения недели. Зелья повторно не выдаются,
а оставшееся время совпадает со сроком в меню.

## Сохранения после регионального пилота

Обновите Lua и ESP из свежего ZIP. На копии слота с возвращённым кольцом
и полученным зельем проверьте диалог Аррилла. Тема `GHSO Claim Supplies`
должна исчезнуть у Аррилла и оставаться у поставщиков Телванни.
В MCM должны отображаться влияние и сроки припасов Телванни.
После сохранения и загрузки проверьте, что уже полученное зелье осталось
в инвентаре, если его не выпили, а сроки поставщиков совпадают с MCM.
