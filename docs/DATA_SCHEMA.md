# Профиль в сохранении

Корень профиля находится в `tes3.player.data.GHSO`.

| Поле | Формат в версии 5 |
| --- | --- |
| `schemaVersion` | Целое число `5`. |
| `player` | Таблица профиля игрока. |
| `player.influenceAwards` | Таблица начислений по ID организации и источника. Значение — положительное целое число очков. |
| `player.claimedPrivileges` | Числовой игровой час выдачи по ID привилегии. Активны `telvanni_supplies` и `telvanni_levitation_supplies`. |
| `player.regionalReputationAwards` | Таблица начислений по ID региона и источника, сохранённая для совместимости с пилотной сборкой. |

Для Телванни первая запись имеет вид `influenceAwards.telvanni.ht_muck = 1`.
Влияние в организации равно сумме её начислений. Запись по тому же
источнику создаётся один раз в каждом сохранении.
Поддерживаемые задания используют тот же формат: ID журнала в нижнем
регистре служит ключом источника.

Региональный пилот приостановлен. В старых сохранениях сохраняются
`regionalReputationAwards["bitter coast region"].ms_fargothring` и
`claimedPrivileges.bitter_coast_supplies`, если они были записаны.
Эти значения не используются в текущей сборке.

- **0 → 1.** Тестовая схема 0 требует явной версии и допускает отсутствие
  `player`. Миграция создаёт недостающую таблицу и сохраняет остальные поля.
- **1 → 2.** Миграция добавляет `player.influenceAwards`; существующие
  поля игрока и корня сохраняются. После миграции интеграция сверяет
  журнал и начисляет влияние за подтверждённое завершение задания.
- **2 → 3.** Миграция добавляет `player.claimedPrivileges`, сохраняя
  начисления и остальные поля. В этой версии первая выдача хранилась
  как `claimedPrivileges.telvanni_supplies = true`.
- **3 → 4.** Старая отметка выдачи припасов Телванни заменяется игровым
  часом первой загрузки со схемой 4. Пустая отметка остаётся пустой.
  Срок следующей выдачи вычисляется прибавлением 168 часов.
- **4 → 5.** Миграция создаёт пустую таблицу региональных начислений
  и сохраняет влияние и часы выдачи.

Core создаёт профиль, когда ключ `GHSO` отсутствует. Неизвестную будущую
версию, корень без версии и некорректные записи Core оставляет как есть и
указывает причину в журнале. Некорректные начисления организации также
сохраняются как есть.
